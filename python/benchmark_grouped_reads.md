# RDF5D grouped-read comparison

The fixture is generated by `bench_grouped_reads.py` in a temporary directory. It
has four named Turtle graphs with 3,000 generated triples each, a shared triple,
and a root → mid → leaf `owl:imports` chain. The fourth graph is outside the
closure. All sources are local and `OntoEnv` runs in offline mode. The generated
triples deliberately overlap across graphs so grouping must collect all graph
contexts. The raw dataset measurements call its store's union `triples` method;
the closure measurements use `env.get_closure(root).triples`.

Reproduce from `python/` on Linux:

```sh
VIRTUAL_ENV="$PWD/.venv" .venv/bin/maturin develop --release
.venv/bin/python bench_grouped_reads.py --triples-per-graph 3000 --repeat 30
```

For the baseline, build the extension from commit `c568665` before running the
same benchmark command. `benchmark_grouped_reads_baseline.json` and
`benchmark_grouped_reads_after.json` contain the raw outputs. Both runs used
Python 3.14.2, rustc 1.98.1, and an Intel Core Ultra 7 255H on x86_64 Linux.
Each query is warmed once, then timed 30 times; the table reports median
release-build milliseconds. Bind and peak-memory measurements are single runs
in fresh benchmark processes, so small differences should not be read as a
stable improvement or regression.

| Pattern | Raw before | Raw after | Closure before | Closure after |
| --- | ---: | ---: | ---: | ---: |
| subject | 0.0061 | 0.0065 | 0.0028 | 0.0027 |
| predicate | 0.2110 | 0.0060 | 0.1984 | 0.0026 |
| object | 0.2212 | 0.0248 | 0.2069 | 0.0074 |
| predicate + object | 0.1981 | 0.0070 | 0.1964 | 0.0031 |
| unbound | 1.3511 | 1.1753 | 0.7296 | 0.7528 |

The raw result counts match before and after: 1 for subject, predicate, and
predicate + object; 31 for object; 3,007 for unbound. The closure has 3,002
unbound triples. Selective predicate and object reads now follow the matching
postings instead of examining each subject. Unbound time is similar.

The after build was also run at 1,000 and 6,000 generated triples per graph
with the same command and 30 repeats; outputs are in
`benchmark_grouped_reads_scale_1000.json` and
`benchmark_grouped_reads_scale_6000.json`. Closure predicate time stayed at
0.0025–0.0028 ms with one matching triple. Closure object time grew from
0.0040 to 0.0135 ms as matching rows grew from 10 to 62. Closure unbound
time grew from 0.248 to 1.548 ms as result rows grew from 1,002 to 6,002.
This is consistent with visiting matching postings for selective reads and
emitted rows for full iteration. The process peak grows with fixture size
because the eagerly built indexes hold more triples; the before/after peak
comparison above uses the same fixture size.

Dataset bind time was 20.25 ms before and 21.23 ms after; closure bind was
2.31 ms before and 1.96 ms after. Process high-water RSS after all queries was
52,500 KiB before and 52,296 KiB after. The scan's temporary memory is bounded
by its per-graph cursors and one result's graph IDs; the eager permutation
indexes still dominate bind-time memory.

## Eager index decision

Keep `Snapshot::build_indexes()` at Python bind time. The measured bind time
and peak RSS are comparable before and after the grouped-read change, while
each bound shape now uses its corresponding already-built index. Removing eager
construction would shift index building into the first query and needs a
separate cold-query and memory study before changing the Python policy.
